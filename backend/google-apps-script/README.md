# 聖誕森林｜Google 收件服務

網站與 DIY 維持目前 GitHub Pages；本服務只集中收取作品圖片、名稱、刻字與祝福。
不用 Supabase、API 金鑰或第三方付費圖庫。

## 第一次設定

1. 用要存放作品的 Google 帳號開啟 [Apps Script](https://script.google.com/home)，新增獨立專案，命名為「格致聖誕森林」。請勿覆蓋其他校務系統。
2. 將本資料夾 `Code.gs` 的完整內容貼到專案內的 `Code.gs` 並儲存。
3. 在上方函式選單選擇 **setupForest**，按「執行」，依 Google 畫面授權此專案管理所需的 Drive 與試算表資料。
4. 執行紀錄會列出新建的「作品清單」與「作品圖片」資料夾連結。重跑 setupForest 會沿用相同資料，不會清空作品。
5. 按「部署 → 新增部署作業」，選「網頁應用程式」。執行身分選「我」，誰可以存取選「任何人」。若學校帳號不提供此選項，須由帳號管理政策處理，或改用能公開部署的帳號。
6. 複製結尾為 **/exec** 的部署網址。不要用 /dev、編輯器網址、試算表網址或 Drive 資料夾網址。
7. 將部署網址交回網站維護者；驗證 `?action=health` 回覆 `service: gj-forest-images-v1` 後，填入 `src/forest/config.js` 的 `forestEndpoint`，再建置部署網站。

目前 endpoint 留空時，網站只有**本機預覽**。「預覽我的樹」不會把作品公開送出，森林會明確顯示尚未連線。
接上正確網址後，按鈕才會變成「送出我的樹」，所有訪客看到同一份清單。

## 活動管理

- 圖片檔案保留在 Google Drive 資料夾中，不需要把整個資料夾設成公開。服務只提供 `published` 記錄的圖片。
- 試算表 Trees 的 `status` 欄：`published` 為展示、`hidden` 為隱藏。隱藏後，森林更新清單時便不再展示；已經開啟的畫面可能仍保留先前下載的圖片，需重新更新。
- 勿修改 `id`、`editHash`、`imageFileId` 與 `lastRequestId`。清單和資料夾都維持原本的私人權限。
- 同一個瀏覽器保有自己的隨機修改憑證，再送出會更新同一棵樹。清除瀏覽器資料或換裝置後，無法自動取回原修改權限。
- 管理者隱藏的作品重新送出時仍保持隱藏，避免繞過管理設定。
- 請保留試算表與圖片資料夾，勿只刪其中一個；需要備份時兩者一併備份。

## 接口與限制

- GET `action=health`：檢查是否初始化完成。
- GET `action=list&cursor=0&limit=24`：讀取公開作品的精簡清單，不含修改憑證或 Drive 檔案 ID。
- GET `action=images&ids=...`：一次最多六張公開作品圖片，以 base64 回傳；降低 Drive 外連圖片與權限問題。
- POST `action=submit`：只接受 PNG/WebP 圖片，最大 180,000 bytes。驗證圖片檔頭、文字長度與作品修改憑證，以 ScriptLock 避免重複列。
- GET `action=receipt&id=...&requestId=...`：確認該次寫入結果。前端不會把不透明的 no-cors HTTP 回覆當作成功。
- JSONP 僅支援上述公開讀取，回呼名稱有白名單；GET 不得新增、修改或刪除作品。
- 每個森林頁面載入最多 24 棵，圖片以六張一批取得，本機圖片快取最多 72 張。分頁可繼續瀏覽其他作品，不同時建立數百棵完整 3D 樹。
- 預設最多 2,000 份作品，可由管理者調整 `FOREST_MAX_WORKS` 並重新執行 setupForest 擴充工作表。
- Apps Script、Google Drive 與 Sheets 仍受 Google 帳號配額限制。正式活動前，請用兩個不同瀏覽器／裝置測試投稿、瀏覽、更新與隱藏作品，再測預計同時投稿的人數。

## 更新程式

修改 Apps Script 後，使用「部署 → 管理部署作業 → 編輯 → 新版本」更新同一份部署，保留 /exec 網址。更新前後皆可用 `?action=health` 確認服務。

## 驗收

用 A 裝置製作並送出；在 B 裝置進入森林並更新，應看到同一棵樹。
A 再送出應更新原作品、總數不增加；B 無法用自己的憑證修改 A 的作品。
把作品 status 改成 hidden 後重新更新森林，不應再取得該圖；斷線或寫入失敗時，DIY 草稿仍保留。
